# Phase 2 — Conformance Harness, Front End, Bytecode: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the correctness backbone (recorder, ~44 recorded fixtures, comparison runner, `fast-check` generator, test262 runner), then the front end (type strip → parse → scopes → subset validator) and a `BytecodeGenerator` whose output matches real `--print-bytecode` for every fixture function, with the AST and Bytecode views as pure emitters.

**Architecture:** Harness first, in `scripts/conformance/` (the only code that spawns real node; erasable-TS `.mts`, see ADR-009) with its tests in `tests/conformance/`. The pipeline lives in `core/` (pure). Bytecode fidelity is enforced by a **ratchet**: each fixture has a recorded status (`pending` → `opcodes` → `exact`) and the test fails on any regression or unrecorded improvement, so the generator grows family by family and ends with documented exceptions only.

**Tech Stack:** `@babel/parser` (+`estree`/`typescript` plugins), Vitest 5, `fast-check` 4, Zod 4 via `@/core/shared/zod`; new dev deps `yaml` (test262 front-matter) and `@types/estree`.

**Spec:** `PROMPT.md` §3.3–3.4, §6.1, §7.1–7.3, §9 Phase 2. Re-read §3 before each core task. V8 source of truth: `https://raw.githubusercontent.com/v8/v8/13.6.233.17/src/interpreter/bytecodes.h` (tag matches `docs/TARGET.md`'s V8 `13.6.233.17-node.51`).

## Verified facts (probed on the pinned Node 24.19.0 — do not re-derive)

- `node --permission main.cjs` runs the entry script with no grants; `fs`/`child_process` inside it throw `ERR_ACCESS_DENIED`. Uncaught-error stderr is `<abs path>:<line>\n<source line>\n<caret>\n\n<Name: msg>\n    at ...frames (incl. node:internal/modules/cjs/loader:1872:14 ...)\n\nNode.js v24.19.0`, exit 1. Unhandled rejection prints the same shape. `.cts` with `enum` fails with `SyntaxError [ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX]: TypeScript enum is not supported in strip-only mode`, exit 1.
- `--print-bytecode` listing: `[generated bytecode for function: NAME (0xADDR <SharedFunctionInfo NAME>)]`, `Bytecode length`, `Parameter count`, `Register count`, `Frame size`, then lines `  POS S|E> 0xADDR @ OFFSET : HEXBYTES  Mnemonic operands` (position column only where V8 attaches one), `Constant pool (size = n)` with `i: 0xADDR <SharedFunctionInfo f>` / `<String[7]: #console>` entries, `Handler Table`. Jumps print `JumpIfTrue [5] (0xADDR @ 51)`. Only functions V8 actually compiled (called ones) are printed. The listing is noisy (~100 Node-internal blocks even for a tiny script).
- The CJS main script compiles as the body of `function (exports, require, module, __filename, __dirname)`: **`Parameter count 6`**, top-level function declarations hoisted as `CreateClosure` at offset 0, free names via `LdaGlobal`. Right after the first `Module.prototype._compile` of `main.cjs` V8 prints a 5-byte anonymous wrapper block (`CreateClosure [0],[0],#0 ; Return`) and then the real top-level block; the latter's constant pool lists every child `<SharedFunctionInfo ADDR>`, and each child's own block header carries that same address. **User blocks are therefore found by walking the SFI-address tree from the top-level block**, not by name filters (`--print-bytecode-filter=` only matches by name; empty value = anonymous functions only; `--no-lazy` explodes the output).
- Slot arithmetic seen in listings: `LdaGlobal [2],[0]` then `GetNamedProperty r3,[3],[2]` then `CallUndefinedReceiver1 r0,r5,[4]` then next `[6]` → global loads, named loads and calls take 2 feedback slots each; verify the rest against fixtures, never from memory.
- Async functions compile to the generator machinery (`SwitchOnGeneratorState`, `InvokeIntrinsic [_AsyncFunctionEnter]`, `SuspendGenerator`, `ResumeGenerator`, `_AsyncFunctionAwait/Resolve/Reject`, handler table `prediction=3`).
- Network access to GitHub raw and npm works from this machine; `llvm-mc` is not installed (Phase 4's problem, not this phase's).

## Global Constraints

- Target is `docs/TARGET.md`; the recorder refuses any other runtime and writes `*.expected.json` only through `npm run conformance:record`. **Never hand-edit an expectation**; a mismatch is a bug in our model (use `superpowers:systematic-debugging`).
- `child_process` is allowed only in `scripts/conformance/**` and `tests/conformance/**`, only on repo-owned or generated programs; `eval`/`Function`/`vm`/`ShadowRealm` stay banned everywhere (ADR-008). Real runs use `process.execPath --permission` with **no grants**, a timeout, a memory cap and an empty env.
- `scripts/conformance/*.mts`: erasable TypeScript only, relative imports **with** `.mts`/`.ts` extension, no `@/` alias (they run under plain Node type stripping; ADR-009). Zod only via `../../core/shared/zod.ts`.
- `core/` is pure TS: only `core/` plus pure npm libs; no Node built-ins, DOM, clock, randomness. `Result<T, Diagnostic[]>` for expected failures; throw only for programmer errors. Branded ids; exhaustive `switch` with `never`. Strict tsconfig flags, no `any`.
- Names follow V8/spec (`BytecodeArray`, `FeedbackVector`, `SourcePositionTable`, `ConstantPool`); comments cite the V8 file or spec operation, not section numbers.
- Subset limits (§7.1): source ≤ 10 KB, ≤ 400 lines. Source offsets are **UTF-16 code-unit offsets into the BOM-less text V8 sees**.
- Every excluded or refused construct yields `Diagnostic { code, message, range, hint }`; never fail silently, never approximate.
- Tests needing the pinned Node use `describe.skipIf(!pinned)` with a printed reason, so `npm test` works anywhere.
- Commit per task, Conventional Commits, ending with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Subset decisions this plan makes (record as ADR-021 in Task 22; now also written into PROMPT.md §7.1; flag for human review)

§7.1 lists the subset but not the glue it needs. **Supported in Phase 2:** the §7.1 list plus assignment and compound assignment, `++`/`--`, conditional `?:`, `new` (for `new Promise`/`new Error`), `this` (methods), `delete`, bitwise operators, comma-free expressions, sloppy and strict (`'use strict'`) scripts, top-level `return` (legal in CJS), `Math.{abs,ceil,floor,max,min,round,sign,sqrt,trunc}` (IEEE-exact), `process.nextTick` only on `process`. **Refused with a diagnostic and hint** (can be added later, one at a time, each with fixtures): classes (stretch goal, deferred), `switch`, `do…while`, `for…in/of`, labeled statements, destructuring, spread/rest, `arguments`, `instanceof`, `in`, `with`, `require`/`import`/`export`, and everything §7.1 already excludes. TS: erasable syntax only.

## Review Focus (inputs the spec implies but "done when" does not exercise)

1. **A fixture that never terminates or floods output** (`for(;;){}`, `setInterval` without clear, 5 MB of logs) must make the real run time out / truncate and the recorder fail that fixture loudly, never hang CI or record a partial result. → Task 2.
2. **Stale, partial or orphan expectations** (`expected.json` for another Node/V8, fixture without expectation, expectation without fixture, `.cts` and `.cjs` of the same name): the integrity test fails naming the file. → Task 3.
3. **CRLF line endings, a leading BOM, astral characters (`"😀"`) and tabs** must not shift offsets: `stripTypes` keeps length and `\r\n`; positions stay UTF-16 offsets of the BOM-less text. → Tasks 7, 8.
4. **Babel `errorRecovery` returns an AST for `let x; let x;`, `return` misuse, invalid assignment targets**: recovered errors must become diagnostics and block bytecode generation. → Task 8.
5. **Validator evasion by aliasing**: `const r = Math.random; r()`, `globalThis.Date`, `this.Date`, `Math['random']`, `var Date = Date`-shadowing tricks, `(0, eval)`. The validator resolves **global references through scope analysis**, not by matching member syntax; a locally shadowed `Date` is allowed, an aliased global is not. → Task 10.

### Task 12: test262 subset runner and vendoring

**Files:** Create `scripts/conformance/vendor-test262.mts`, `tests/conformance/test262/{metadata,classify,runner}.ts`; Test `tests/conformance/test262.test.ts`; Create `vendor/test262/{COMMIT,exclusions.json}` and the vendored tests.

**Interfaces — Produces:**
